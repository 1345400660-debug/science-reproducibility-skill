# 论文复现工作流

把论文复现拆成可核查的步骤：从论文取证、规格拆解，到最小运行、自实现、自证、受控实验和结论交付。重点处理“论文没写清楚”“没有官方代码”和“结果对不上时如何定位”。

**第一次使用，建议从 C 通用版开始。** 下载后读取手册与精简提示词即可；需要接入技能加载机制时，再选择 B 版。

本仓库提供工作方法、提示词和技能定义。具体论文的代码、数据、模型权重、Python 环境及计算资源需要另行准备。

## 选择版本与下载

| | C · 通用版 | B · DSH 兼容版 |
|---|---|---|
| 下载 | [C-通用平台版.zip](C-通用平台版.zip) | [B-DSH版.zip](B-DSH版.zip) |
| 包含 | 完整手册、精简提示词、使用说明 | 方法论、`paper-repro-pipeline` 技能、五份纪律文件、工作区约定模板 |
| 使用方式 | 提供手册并粘贴指令，或人工执行 | 放入工作区及宿主支持的技能目录 |
| 外部技能 | 不需要 | 增强技能可选；随包五份纪律文件必需 |
| 适合 | 不确定平台兼容性、纯对话、人工阅读 | 已确认宿主支持该定义与加载方式 |
| 验收重点 | 会话能读到手册并遵守范围 | 技能识别成功，方法论和参考文件可读 |

两个版本共享方法论来源，但修订进度和编排规则有差异，**不要同时加载两套规则，也不要假定正文逐字相同**。更换版本时使用目标版本的完整文件集。

下载方式：

1. 点上表的 ZIP 文件，在文件页面下载原始文件。
2. 也可下载整个仓库，再找到其中的 B/C 分发压缩包。
3. 已安装 Git 的用户可运行：

   ```bash
   git clone https://github.com/1345400660-debug/science-reproducibility-skill.git
   cd science-reproducibility-skill
   ```

下载整个仓库后，分发 ZIP 需要再解压一次。以看到对应说明文件为准。

可用 [SHA256SUMS.txt](SHA256SUMS.txt) 核对两个分发包，命令见[常见问题](docs/常见问题与升级.md)。

## C 版快速开始

1. 解压 `C-通用平台版.zip`。
2. 将 `论文复现工作流-通用手册.md` 提供给当前会话或支持资料上传的项目。
3. 将 `系统提示词-精简版.txt` 的完整内容放入可用的项目指令区域；没有指令区域时，先在对话中粘贴。
4. 提供论文、目标、数据位置和资源预算，先做只读检查。

```text
请按我提供的《论文复现工作流-通用手册》处理附件论文。
本轮只读，不安装依赖、不运行代码或训练。
先确认你实际读到的手册与论文文件，再给出：
1. 论文身份、目标实验与指标；
2. 官方代码线索及核实状态；
3. 预处理、数据划分、训练协议和未明确参数；
4. 最小验证计划、所需资源和阻断项。
不要把计划写成已经执行的结果。
```

应看到带出处的规格清单、代码可用性判断和执行计划。仅回答“已理解”不算验收通过。

上传手册不会自动提供终端、GPU 或文件访问能力。只有具备相应工具且任务允许执行时才能运行，否则输出计划与本地执行步骤。详见 [C 版完整说明](docs/使用-C版.md)。

## B 版快速开始

1. 解压 `B-DSH版.zip`。
2. 将 `复现工作流/` 放在论文项目根目录。
3. 将 `skills/` 中两个目录放到宿主实际支持的技能根目录，保持同级。
4. 将 `AGENTS.md模板.md` 的规则合入工作区约定；已有 `AGENTS.md` 时不要直接覆盖。
5. 替换 `<工作区根目录>`，让 Agent 执行只读安装验收。

以下是**宿主支持项目级 `.agents/skills/` 时**的示例布局：

```text
my-reproduction/
├── AGENTS.md
├── papers/
├── 复现工作流/
│   ├── 速查卡.md
│   ├── 复现工作流.md
│   ├── 实测记录.md
│   └── README.md
└── .agents/skills/
    ├── paper-repro-pipeline/SKILL.md
    └── ai-research-reproduction/references/
        └── 五份随包纪律文件
```

`ai-research-reproduction/` 在此包中只提供参考文件，**不是完整的同名技能**。已有同名目录时先备份、逐文件比较，不要覆盖整个完整技能。

具体步骤、路径替换与验收命令见 [B 版安装说明](docs/安装-B版.md)。

## 第一次任务怎么提问

把下面方括号内容换成实际信息：

```text
论文：[PDF 文件/标题/论文编号]
目标：[例如复现 Table 1 的某个实验]
执行方式：[只做计划 / 最小运行 / 已授权的有限实验]
代码来源：[官方仓库路径或链接 / 尚未找到]
数据：[本地路径、获取方式或尚未准备]
环境：[系统、Python、CPU/GPU、内存；未知项写未知]
预算：[最大运行时间、磁盘和计算限制]
允许操作：[是否能联网、安装依赖、执行外部代码、训练]
输出目录：[项目路径]

先核对论文规格和现有文件。只在以上范围内推进，
把未执行、未验证、无法判断的部分明确标出来。
```

继续已有项目、异常诊断、官方仓库不可用、扫描和交付的模板见 [任务模板与验收](docs/任务模板与验收.md)。

## 工作流程与交付物

| 阶段 | 工作 | 应留下的证据 |
|---|---|---|
| 0 接收定位 | 明确目标、范围、文件和预算 | 任务边界、资源清单 |
| 1 取证 | 核对论文身份、正文质量、代码来源 | 出处、代码可用性 |
| 2 拆解 | 抄齐预处理、公式参数、训练与评估协议 | 规格表、缺失参数和风险 |
| 3 最小运行 | 验证最小入口 | 命令、配置、日志与失败原因 |
| 4 实现 | 实现或核对方法 | 代码与规格对应关系 |
| 5 自证 | 数值、梯度、退化/等价性检查 | 检查脚本、结果及缺失项 |
| 6 受控实验 | 基线、授权范围内的对照与扫描 | 配置、种子、预算和结果 |
| 7 推断 | 对未明参数提出可检验解释 | 假设、证据与未决项 |
| 8 核验 | 独立重算、稳定性与归因检查 | 重算结果、反例与限制 |
| 9 交付 | 汇总结论、代码和证据 | 报告及运行说明 |

推荐结果结构：

```text
复现项目/
├── 报告/          # 结论、对比表、证据与限制
├── 代码与图表/
│   ├── repro/     # 实现与独立验证脚本
│   ├── figures/
│   ├── results/   # 日志、配置和指标
│   ├── data/      # 或数据获取说明，按数据许可处理
│   └── README.md  # 环境、入口、复算方法
└── 过程记录/      # 拆解、排查、勘误；保留在工作区
```

对外交付以报告和可复算材料为核心。过程记录留档；最终报告仍需保留影响结论的限制与不利结果。

## 适用范围与验证状态

更适合可通过数值实验检查的论文，尤其是无官方实现时的规格拆解与自证。纯理论证明、专用硬件或无法取得的数据需要另定验证方法；不能因为按流程走完就宣称整篇复现成功。

方法论包含既有复现实例及事故记录；实例数字属于对应配置与环境，不是新项目的预期结果。

2026-10-18 的通用版修订通过三名独立评审、八个情景干跑及分发包检查。**这不是重新训练验证，也不保证任意平台自动加载技能或获得论文同等指标。**

安装说明的验证记录见[文档验收记录](docs/文档验收记录.md)。更新详情见 [CHANGELOG.md](CHANGELOG.md)。
