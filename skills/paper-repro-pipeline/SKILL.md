# 论文复现工作流

## 入口与资料

本技能自包含。下列链接相对于本文件所在目录解析，不相对于论文工作区。不要要求用户另外安装同名宿主技能或把方法论复制到项目根目录。

1. 读取[方法论](references/workflow.md)的第一部分速查卡和第二部分编排；随后只读当前阶段的详细章节。
2. 进入实质复现前，读取随包的[代理行为](references/agent-operating-principles.md)、[科研严谨性](references/research-rigor-principles.md)、[实验规范](references/deep-learning-experiment-principles.md)、[研究安全](references/research-safety-principles.md)和[踩坑清单](references/research-pitfall-checklist.md)。
3. 当前阶段所需资料不可读时，报告具体缺失路径，先修复材料获取；不凭记忆宣称已加载。用户仍可要求先做不依赖这些资料的其他工作。
4. 调试、训练、查论文等外部技能均为可选；根据实际能力完成任务，不声称调用了不存在的工具。

通用资料包由本入口与同一批参考文件自动生成；其中“资源”章节等价于文件读取。只读当前阶段所需章节，无需每轮重复加载全文。

## 任务范围与证据

用户当前任务与已授权范围决定是否执行。只要求方案或阅读时不安装、不运行；已明确授权的操作不重复索要许可。新增变体、替换数据或改变实验协议、训练/评价语义超出原授权时，先记录提案并请求相应决定。恢复既定语义的实现修复可在已授权范围内推进。

用户要求官方仓库复现时，保留该路线；仓库不可用则记录阻断，不擅自改成自实现。允许无代码自实现时，才进入 L2。

保持实际执行、计划、推断与未验证分开。安装或冒烟成功不等于论文复现成功；失败和不利结果同样留痕。历史案例的数字、路径与当时环境仅作证据说明，不是当前机器事实或通用阈值。

## 按任务推进

在现有项目先读最新工作日志、配置与真实结果，恢复状态，不重复已完成且有证据的工作。

| 当前任务 | 读取方法论位置 | 本阶段证据 |
|---|---|---|
| 核实论文、正文提取质量、官方代码线索 | 阶段 1，尤其 1.2 / 1.4 | 身份、出处、可用性与未决项 |
| 拆规格、预处理、公式参数、训练/评估协议 | 阶段 2，尤其 2.2 / 2.2b | 规格表、数据分工、假设与预算 |
| 最小运行、自实现、正确性检查 | 阶段 3–5 | 命令、日志、配置、数值/梯度/等价性检查 |
| 指标异常、NaN、慢收敛 | 阶段 6.1 | 具体错误证据、可检验解释、受控诊断 |
| 对照、有限扫描、推断缺失参数 | 阶段 6–7 | 控制变量、授权候选、资源消耗、失败组 |
| 复算、稳定性、结论和交付 | 阶段 8–9 | 独立验证、限制和可复算材料 |

代码关键词只提供线索。L1 要核对可达性、官方归属、方法/入口对应，以及目标环境可行性；没有执行时记“运行未验证”。未找到实现时记录检索范围；核实或运行受阻时标记 `L1-blocked` 并保存原因。

已有具体错误证据先诊断；只有证据不足以区分慢与错时，才在授权预算内做单因素实验。不要把增加训练预算变成排查错误的前提。有限扫描仅支持已覆盖范围内的观察。

根据十轮复盘形成的[证据与交付检查](references/evidence-and-delivery.md)：写自检或使用断点续跑时读第 1–2 节；修改验收判据时读第 3 节；整理对照表、摘要或交付包时读第 4–6 节。检查通过数只描述该检查覆盖的性质，不直接转换成论文复现成功。打包时可运行随包的[交付核对脚本](scripts/verify_delivery.py)，路径和必需文件由当前项目确定。

## 保存结果与继续工作

默认将报告与证据放在 `报告/`，实现、图表和结果放在 `代码与图表/`，排查与交接放在 `过程记录/`；用户已有布局时沿用并记录映射，不为了套模板搬动项目。

每次实际运行保留入口命令、环境、配置、种子、数据版本、日志与结果位置；只读任务无需制造空运行记录。收尾逐条区分已验证、未完成、无法判断，保留不利结果和比较条件。

最终报告按[方法论阶段 9.4–9.5](references/workflow.md)先核对逐实验对照表，再新增独立的“读者摘要”。原有总结的内容、结构和生成要求保持不变，不用摘要替换或改写。摘要用普通中文说明做了什么、结果如何、不能说明什么，不得新增表中没有依据的数字或原因；若原总结与核实证据冲突，在摘要中注明具体分歧，不静默修改原总结。

阶段正常结束且仍在任务范围内时继续推进，给必要进展说明；资源超界、必须由用户选择的路线或用户要求停止时才暂停相应工作。

人工验收可使用[任务模板](templates/task-prompts.md)。用户需要工作区约定时，可合入[工作区模板](templates/AGENTS.md)，不要覆盖现有约定。
