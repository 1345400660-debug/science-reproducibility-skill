# 从十轮复盘落实到执行的检查

来源是用户提供的十轮交付复盘（report_1–report_9、report_Complexity），另含 TTN 工作流实测。案例编号对应复盘 A/B/C；原始实验不随技能分发。复盘中的数字和归因仍需原证据支持，不能当作当前任务的已验证事实。

## 1. 自检必须覆盖可能出错的环节

触发：A-11 的输入编码无效、A-12 的漏单元和键覆盖，以及 TTN 补充案例 A-15 的端点检查失灵。

- 在现有 smoke 清单旁标明每项检查验证什么、不能验证什么。归一化正确不能验证初态、预处理或编码参数正确；数值与报告一致不能验证数值与论文一致。
- 对当前实现的高风险环节，选择一个最小错误变体作为负对照：例如交换轴序、错误初态、漏一个实验单元。正确实现应通过，错误变体应被检测到。不要求为每个普通检查制造错误版本。
- 不变性在非退化输入下检查；小规模能枚举时用精确枚举。仅测试 p=0 等端点不能检验 dropout 缩放位置。
- 数据分工与输入表示纳入启动检查：提取器/分类器/验证/测试分别使用哪些数据，样本数、划分和预处理是否符合本轮冻结规格。样本数相符仍不能证明样本身份相符。
- 聚合键包含实验、配置、阶段和种子，遇到重复键报错；将期望实验清单与实际产物对账，失败/缺失单元保留，不用 `except: pass` 隐去。
- 对核验结果先检查必需字段是否存在、类型是否正确，再检查值。不能用预期值补缺失字段后报通过；缺少总数时不能把 `n_pass=14` 写成“14/14”。

## 2. 仅在采用断点续跑时检查恢复语义

触发：A-10 的 BFS 恢复丢失后继集合，文件仍存在、程序仍完成，但结果错误。

列出所有跨调用状态：已处理集合、待处理队列、已生成后继、聚合量和随机数状态；训练另含优化器、调度器与进度。记录实际保存项，只有权重时不宣称精确续训。

用可承受的小实例比较“一次完成”和“处理中途停止再恢复”，覆盖实际有状态变更的阶段，包含正常预算退出。比较最终指标、覆盖集合与关键不变量，而非只比文件个数。确定性计算应一致；非确定性运行先约定合理容差和比较方法，不能事后放宽。

测试发现状态污染时隔离旧产物并记录影响范围，从可信状态重建；不要混入新聚合结果。历史的 10 分钟限制不是通用预算，按当前执行器实际限制设置。

## 3. 判据修订必须可追溯

触发：A-05/B-07 的有限规模结果被误用渐近判据；A-12/A-13 的核验工具自身出错。

失败后先区分实现错误、检查错误、协议差异和证据不足。修订检查或阈值时，在过程记录追加：

| 检查 ID / run ID | 原判据与首次失败 | 修订内容 | 独立依据 | 影响范围 | 重验及未决项 |
|---|---|---|---|---|---|
| 当前检查 | 原命令、值、阈值、日志位置 | 新旧差异及日期 | 论文适用域、推导或独立参考 | 哪些结果/图/报告须更新 | 新结果及仍未验证的范围 |

保留旧记录及版本，不覆盖首次失败。论文锚点与我方验收判据分开存放；若确认锚点抄录错了，保留原值、原出处和更正依据，建立新版本，再评估受影响结果。不能靠“不改锚点”掩盖不断放宽验收标准。

有限规模核验通过不证明渐近定理；新增检查改变分母时解释为何从 19 项变为 22 项，不把通过率提升单独当成研究进展。

## 4. 对照表和摘要使用同一份已核对证据

触发：B-04 的文件一致性全通过但 Fig.8 未定量复现；总览与 B-04 的参数口径混用；B-05 硬件未执行。

沿用方法论 9.4–9.5 的对照表和独立读者摘要，原有总结不动。每项判断的最小对应关系为：

`实验 ID → 论文版本/位置/主张 → 配置与数据角色 → run ID/结果字段 → 检查覆盖范围 → 判断`

- 核对数字时同时核对指标、单位、参数、数据规模、预算、种子数和汇总方式。不同 β 的论文数值不能拼成同一实验的比较目标；单 seed 最佳值不能对比多 seed 均值后声称改善。
- 分开记录“执行状态”“实现/文件检查”“论文主张支持程度”。`all_pass=true` 只报告其检查含义；未执行硬件不能由模拟检查通过代替。
- 证据不足时用“当前配置未达到论文结果；原协议尚不完整”，不要升级为论文失败。具体公式的不一致只针对该公式；只有评估依赖关系后才能说明其对某个主结论的影响。
- 用锚点反推参数属于拟合该锚点的候选解释，不是独立验证，也不能证明作者实际代码如此。优先寻找未用于反推的证据；没有则披露循环验证风险。
- PDF 文本与公式冲突时核对渲染页和上下文，先排除提取伪影。图上估读单独标明，不冒充精确表值；已有图不可读数时保留无法比较。
- 摘要先解释实际完成和未完成的范围，再说明结果。术语首次出现给通俗解释；不让读者凭“L2”“22/22”自行推断成功。
- 摘要、表格、图注使用相同结果来源。发现旧总结冲突，在摘要列“原说法—当前证据—当前判断”，不静默改写旧总结。没有独立依据的归因写成假设。

## 5. 交付前验证实际产物

触发：A-01–A-04 的生成脚本错误、A-12 的空图与漏图、A-18 的打包漏报告；C-W01 记录的旧图残留。

结果修订后，重新生成受影响的图和新报告部分；原总结继续保留。真正运行生成入口，检查预期图的面板、曲线和数据来源，不能只依赖 exit 0。缺少源数据或预期曲线时报告失败；合法空结果则显式标注原因。

以本轮认可的交付暂存目录为基准，记录结果文件哈希、图表生成输入、报告使用的结果字段及配置/run ID，确认它们属于同一轮。时间戳与 ZIP CRC 只能辅助定位，不能证明内容对应最新结果。

打包后运行随包脚本（路径由实际技能安装位置与项目布局替换）：

```text
python <技能目录>/scripts/verify_delivery.py --source <交付暂存目录> --archive <交付包.zip> --prefix <包内顶层目录> --required README.md --required 报告/01-复现报告.md
```

`--source` 指定包内顶层目录对应的目录，不是包含缓存等无关文件的整个工作区；已有交付布局保持不变。按约定传入所有必需文件，不能只复制示例的两项。根目录直接放文件的 ZIP 使用 `--prefix ""`。

脚本校验必需文件、归档完整性、重复/不安全路径、逐文件集合与 SHA256；缺失、额外或过期文件非零退出。它不执行实验、不解压、不验证科学结论，也不判断源目录本身是否过期。图的实际内容和结果来源仍需上一段的核对。

## 6. 环境与证据缺失

路径、CPU/GPU、网络、内存、运行时限均以当前环境探测为准；复盘的 Linux `/workspace` 和旧包版本只属于历史。引用路径不存在时标为“原证据当前不可访问”，不要复用旧 PASS 日志宣称本轮已验证。保留已完成的检查及未覆盖项，能继续独立工作时继续。
