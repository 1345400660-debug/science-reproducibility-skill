### 零、工作节奏：还在正常推进，就不要停

**每个阶段的交付物是一个「文件」，不是一次「汇报」。**

**判据是"有没有出问题"，不是"阶段有没有结束"。** 阶段 2 拆完、阶段 3 冒烟通过、
阶段 5 自证通过——这三件事都不构成停下来的理由，直接进入下一阶段。

**只有这七种情况该停下来找用户**：

| # | 停的条件 |
|---|---|
| 1 | 阶段 0 必读的方法论或随包纪律资料读不到；可选外部技能缺失不阻断 |

### 一、九条原则

| # | 原则 | 一句话落地 |
|---|---|---|
| 1 | **先取证，再动手** | 写代码前查真伪、找代码、核版本 |
| 2 | **先验输入质量** | PDF 文本提取先做探针，失败就切视觉/OCR，不要硬读 |
| 3 | **能扫的别问，能反推的更别问** | 只有真推不出来的才问作者 |
| 4 | **没代码就自证** | 数值对照 / 梯度校验 / 等价性对照；**第三个不一定存在，缺了要显式标注** |
| 5 | **★ 暴露诊断量** | 中间步骤打印一个**可解释的量**，别只看最终指标 |
| 6 | **控制变量 + 多种子** | 单次运行的数字不算证据 |
| 7 | **结论分三级** | 能推翻 / 不能推翻 / **无法判断**。**"无法判断"不是失败** |
| 8 | **★ "完成"不是终点** | 宣布完成后**再回头做一遍系统复查** |
| 9 | **★★ 论文写明的参数，抄完再抄一遍** | ✍️ 函数形式抄对、参数值抄错 = 全错，**且所有自检都发现不了** |

### 二、七条红线（违反任何一条，都可能把自己的 bug 报成论文的问题）

> ★ **用法**：这几条不是"事后教训"，是**动手前要自问一遍的问题**。
> 每进一个阶段，先问一句"这一步会不会踩到下面哪一条"，再动手。

1. **预处理/归一化逐条抄表。** 搜 `normaliz* scale standardiz* norm rescal* preprocess whiten clip`，
   每处抄进表对着代码打勾。
   ⚠️ **术语按词形查**——"globally **re-normalized**"（重整化）≠ "normalized"（归一化）。
   ⚠️ **训练协议三件套默认必查**：`batch`（批次大小）、`learning rate` 的衰减调度、`epoch` 数。
   这三样最常见的不写，**全文零命中就该在拆解阶段记一条警报**（本次 dropout 就栽在 batch 没写）。
2. **★ 带参数的公式，参数值必须单独抄一遍。** 关键词搜不到它（常在散文和图表 caption 里）。
   > 事故：编码参数 **a = 0.1 写成 π/2**，差 **15.7 倍**，F1 虚低 **0.0949**，
   > **四项冒烟测试全绿**（$\cos^2+\sin^2=1$ 对 *a* 取任何值都成立）。
   > **检查必须能对错误的实现失败，否则它只是让人安心。**
3. **★ 检查只能验证"给定输入之后的数学"。** 数值对照 / 梯度校验 / 等价性对照，
   测的全是"输入进来之后算得对不对"；**输入表示、缩放位置、正则项、归一化、编码参数
   这类"数学之外"的选择，三件套一个都测不到**。本次同族踩了三次（编码参数 #16、
   输入被换成裁剪 #31、dropout 缩放位置 #32），**三次都是 8/8 冒烟 + 5/5 自证全绿**。
4. **★ 论文给的超参值，先验它的数值量级。** 读到带数值的超参，当场算它在论文自己
   尺度下的效应——γ=0.01 让惩罚项比 NLL 大**四个数量级**（压塌模型）、init 0.4 在 b=2/T=8
   下让 |f| 初始化就到 **1e193**（float64 溢出）。**量级离谱，先怀疑论文的数值，再怀疑自己。**
5. **带阈值的算法先做方向性自检。** 问"这个判据随参数增大是变松还是变紧"。
6. **诊断量按类别、按层拆开。** 不能只报总体均值。
7. **"完成"之后系统复查。** 清单见详细文档阶段 9.0。

### 三、结果对不上时：先做六问，别急着改实现

```
① 论文写明的参数，我抄错了吗？          ← 先查这个（原则 9）
② 输入本身可分吗？（看类间差距）        ← 差 1 个数量级 = 数据没问题
③ 换一个"已知更好"的表示，同一套代码能上去吗？
      能 → 我的代码没坏，是输入表示不对
④ 这个表示的"表达上限"是多少？（k-NN 等不依赖模型假设的方法测）
      上限本身就低于论文值 → 再怎么调模型也没用
⑤ 诊断量能定位到具体环节吗？
      前处理/数据分工 / 结构拓扑 / 判据阈值
⑥ 都不行 → 结论落入"无法判断"级，**不是"推翻论文"**
```

> **顺序很重要**：①和②几乎零成本，"结构拓扑"那类猜测成本极高。
> 顺序反了，就会拿着一堆自己编的假设去解释一个抄错的数字。

### 四、自证的三件套 + 三件容易漏的

| 校验 | 做法 | 通过标准 |
|---|---|---|
| 数值对照 | 核心算法 vs 一个慢但显然正确的实现 | < 1e-12 |
| 梯度校验 | 解析梯度 vs 中心差分 | < 1e-8 |
| 等价性对照 | 找一个"必须退化成 X"的边界情况 | 逐位相等（**不一定存在**） |
| **不变式对照** | 带约束的优化器：投影落切空间 / 约束每步保持 / $R_W(0)=W$ | 机器精度 |
| **退化开关** | 新代码在某个极限下必须逐位等于**已验证的旧代码** | 逐位相等 |
| **记账稳定性** | 测 $A-B$ 前，换 ≥2 种记账方式各算一遍 | **符号稳定**才算数 |

**写暴力参考实现的三个硬要求**：①在**全输入空间**对，不是抽样 ②生产是实数也要跑**复数**用例 ③留一条退化回旧实现的开关。

> ★ **论文为一个"不变性"引入的系数，要直接测那个不变性**，别只测端点。
> 事故：论文 Eq. 16 的 dropout 系数 $1/(1-p)$ 乘的是**整个 rank-1 分量**，我把它同时乘到了分量因子 $\tilde a$ 和**全部 b 条腿**的 $a$ 上（等价于 $(\lambda/(1-p))^{b+1}$，b=4 时 5.95 次方）——
> **第 1 个 epoch 就 `loss nan`**。而"dropout(p=0) 必须是恒等"这条检查**全绿**：
> p=0 时 $\lambda\equiv1$、$1/(1-p)=1$，**任何缩放位置都满足它**。
> 改成精确枚举（T=2 时只有 4 个分量，$2^4=16$ 种掩码按 Bernoulli 权重加权）后：
> **对版 3.6e-16，错版偏 35 倍**。（详细文档第 32 条）

> **完整做法清单见详细文档 §四**（按动手前 / 自证 / 定位 / 对照统计 / 可视化 / 收尾六组，每条标注由哪个事故触发）。
> 上面这些只是最容易漏、代价最大的几条。

> **记账稳定性为何单列**：测 $W_1-W_0$ 的中心/边缘结构时，两个权重向量相对差只有 **2.3e-4**，
> 而"各自归一化到单位长度"这一个选择单独就注入 **2.15e-4**——**和信号一样大**。
> 同一个统计量只因归一化方式不同就从 **+0.0457 变 +0.0239**（差 90%）；
> 再做缩放扫描，符号在 **+0.061 到 −0.003** 之间来回穿零。**符号不稳，就记"无法判断"。**

### 五、三条措辞硬要求

1. **不说"论文错了"，说"我没复现出来"。** 第一嫌疑永远是自己。
2. **★ 对自己不利的结果必须一并报出。** 只报有利的那条 = 把没有证据的结论塞给读者。
3. **"数字对得上" ≠ "方法被验证"。** 后者需要：去掉方法的基线 + **同维度**对照。

**图上读出的数不能进表格**（只用于定性趋势）。拿不到论文曲线就判「**不可检验**」，
然后改做**内部对照**（同维度经典基线）——"不可检验"和"没做到"是两回事，要显式写出来。

### 六、工程坑速记

- PowerShell 重定向写 **UTF-16**；同一批日志编码可能不统一 → 读日志一律带 `read_any`
- PowerShell **不支持 heredoc** → 写成临时 `.py` 或 `python -c`
- GBK 控制台遇非 ASCII 抛 `UnicodeEncodeError` → `$env:PYTHONIOENCODING="utf-8"`
- 并行 + 大矩阵 → 在 **shell 层**设 `OMP_NUM_THREADS`，进程内设已经晚了
- matplotlib 缺字形**不报错**，只在 stderr 提示
- ★ `np.real(ArrayBox)` **静默切断 autograd 追踪** → 症状是**梯度精确全零、有限差分却正常**，
  只给一条 `UserWarning: Output seems independent of input`。**求导包装一律用 `anp.*`**
- ★ **能写成 batched matmul 就别用 einsum**：实测快 **4–20 倍**（`c_einsum` 是朴素嵌套循环）；
  且 `np.einsum` 会**拒绝一部分纸面上合法的下标**（共享自由指标与独有指标交错时直接报广播错）
- ★ **有 GPU ≠ 能用**：先 `import torch` 试一下，别看到 `nvidia-smi` 就按 GPU 排时间
- ★ **优化之前先剖面**：把时间拆到「前向 / 反向 / 最大的那个中间量」的粒度，
  不许从"调用次数多"直接推到"这里慢"（猜错过一次，改动反而更慢）
- ★ **区分“学得慢”和“实现错误”**：先查报错、有限值、输入规格和更新链路；已有具体错误证据就诊断修复。仅证据不足时，在授权预算内改变一个因素做受控诊断；不要求加预算或三项试遍，无法区分则记“无法判断”。
- ★ **不要用 shell 文本替换就地改方法论文档**：`Set-Content -NoNewline` 会把整个文件压成一行、
  `>` 重定向写 UTF-16。改大文件前先留副本、改完立即验行数/结构（本次把 `复现工作流.md` 压平过）

# 第二部分 · 编排：九个阶段与门禁

> 这一部分回答"**现在该做什么、该读哪一节、什么时候该停下**"。
> 它不替代第三部分的详细手册——**每个阶段动手前，先去第三部分读对应章节**。

## 2.1 工作节奏：还在正常推进就**不要停**

**判据是「有没有出问题」，不是「是不是到了阶段边界」。**

- **一个阶段的产出是「文件」，不是「汇报」。** 拆解表进 `过程记录/`、日志进 `results/`、
  报告进 `报告/`——**文件写完就继续下一个阶段**，不要以"汇报 + 等待"收尾。
- **不要在一个阶段【正常】结束的时候把控制权交还用户。** 停一次就等于要求用户打一次"继续"。
- **也不要反过来**：不停 ≠ 什么都不说。出了问题该停就停。

**该停下来的时候（这些都是"真出问题了"）：**

| 情况 | 为什么必须停 |
|---|---|
| **加载门禁失败**（方法论文档读不到） | 没有可执行内容 |
| **真的推不出来的参数** | 能扫的、能反推的、能按常识推断的——**一律别问**，自己解决 |
| **结果对不上，而且自己定位不了** | 需要用户判断方向或授权换路线 |
| **发现论文有实质问题 / 与预期严重不符** | 属结论级事项，不该单方面定 |
| **资源或算力超出合理范围** | 需要用户决定是否继续投入（**要先实测，不许估**） |
| **交付与复查阶段** | 终态 |
| **用户主动要求** | — |

**技术上的卡壳不算"出问题"**：读报错 → 定位 → 改，自己解决。
**不要把"我接下来打算做什么"当作需要批准的事项。**

## 2.2 九个阶段的分工

| 阶段 | 做什么 | 产出 | 该读第三部分的哪一节 |
|---|---|---|---|
| **0 · 接收与定位** | 明确复现目标（跑通？验证结论？找问题？） | 一句话目标 | 一、何时使用 |
| **1 · 取证** | 验真伪、找代码、提取正文 | 真伪结论 + 复现等级 | **1.1 / 1.2 / 1.3 / 1.4** |
| **2 · 拆解与风险评估** | 填拆解表；抄齐预处理、公式参数、**训练协议** | 拆解表 + 缺失参数清单 | **2.1 ~ 2.5**（尤其 **2.2b**） |
| **3 · 冒烟测试** | 实现最难的一两个模块 + **顺手写暴力参考实现** | 可运行的 smoke test + 数值对照 | **3.1 / 3.2** |
| **4 · 从零实现** | 严格对齐论文写明的部分；猜的标 INFERRED | 完整代码 + 诊断量 | **4.1 / 4.2 / 4.2b / 4.3x** |
| **5 · 自证正确** | 数值对照 / 梯度校验 / 等价性对照 | 校验脚本 + 通过记录 | **5.0 / 5.0b / 5.1 / 5.2** |
| **6 · 受控实验** | 先 baseline，再全范围扫描 + 多种子 | 带误差棒的对比表 | **6.1 / 6.2** |
| **7 · 反推与推断** | 用论文数字反推设置，不问作者 | 定位到的设置 | 阶段 7 |
| **8 · 自查与核验** | 独立重算脚本 + 异常信号清单 | verify 脚本 + 勘误 | **8.1** |
| **9 · 结论分级与交付** | 三级分级 + 措辞 + 交付包 | 报告 + 交付结构 | **9.0 ~ 9.3** |

**关键点**：阶段 3 和阶段 5 **不该分开做**——写 smoke test 时顺手写参考实现，
两阶段的成本几乎为零（实测数值对照误差 5.6e-16）。

## 2.3 加载门禁（开工前必须先做）

开工前按顺序完成下面两步，**任何"跳过"都要有理由**：

1. **读方法论文档**：先看第一部分速查卡（一页），需要时再查第三部分对应章节。
   **读不到就停**——它是唯一权威。
2. **读取随包的五份纪律资料**：代理行为、科研严谨性、实验规范、研究安全与踩坑清单。
   技能入口提供对应链接；通用资料包将它们合并成“资源”章节。资料不可读时先报告并修复获取方式。
   调试、训练、原文查询类的外部技能仍是可选增强，未安装不阻断本工作流。

### 全局执行范围

所有阶段均遵守用户已授权的任务范围、参数集合和资源预算。只要求读取或方案时不得运行实验；已授权的扫描直接推进，不扩大参数集合或重复询问。恢复既定语义的修复可继续；新增变体或改变协议、训练和评估语义须有相应授权。下文“全范围”仅指已授权的有限候选范围；有限扫描只支持该范围内的观察，不能证明所有可能取值下结论成立。

## 2.4 判定复现等级，走对分支

| 等级 | 判据 | 走哪条路 |
|---|---|---|
| **L1** 有可用官方代码 | 链接可达、官方来源可确认、包含对应方法和入口，且最小运行可行性探测通过 | 先跑官方，再核对协议和结果 |
| **L1-blocked** 官方代码存在但不可用或尚未确认 | 记录链接、失败检查和未决原因 | 在原任务允许自实现时按 L2 执行；若指定只复现官方仓库，报告阻断 |
| **L2** 未找到可用官方实现 | 核查正文、附录、代码声明和作者提供的项目链接后仍未找到 | 自实现 + 三件套自证；结论写“本次未找到”，不宣称不存在 |

**L2 是常态而非例外**（实测三篇论文全是 L2）。L2 下**阶段 5（自证）和阶段 8（核验）权重最高**
——论文没给代码，**没有任何外部参照物能替你证明实现是对的**。

## 二、九条核心原则

> 这九条比后面的步骤更重要。步骤可以按情况裁剪，原则不能。

1. **先取证，再动手。** 写代码前先查论文真伪、找代码仓库、核版本。省的是几天。
2. **先验输入质量，再谈方法。** 文本提取可能失败（空格丢失、乱码、无文本层）——**先做探针，失败就切视觉/OCR，不要硬读**。
3. **能扫描的维度就别问，能反推的就更别问。** 只有真的推不出来的才问作者。
4. **论文没给代码，就必须自证正确。** 数值对照、梯度校验、等价性对照。**前两个几乎总能做，第三个不一定存在——缺了要显式标注。**
5. **★ 暴露诊断量，别只看最终指标。** 在关键中间步骤打印一个**可解释的量**（如"截断保留了多少重量"）。结果不对时，它能在几秒内告诉你**是哪一步、差多少**，而不是让你瞎调超参。
6. **控制变量做对照，多种子做统计。** 单次运行的数字没有判断价值。
7. **结论分三级：能推翻 / 不能推翻 / 无法判断。** 混在一起说必然失真。**"无法判断"不是失败，是诚实的结论。**
8. **★ "完成"不是检查的终点。** 宣布完成之后**再回头做一遍系统复查**。

   > 实测：影响最大的一处错误（漏了特征归一化，造成 0.12 的虚假差距）是**在宣布完成之后、应要求复查时才发现的**。
   > 如果没查，就会把**自己造成的差距当成论文的问题**报出去。

9. **★★ 论文写明的参数，抄完之后要再抄一遍。** 函数形式抄对、参数值抄错，等于全错，   而且**所有自检都发现不了**（$\cos^2+\sin^2=1$ 对参数取任何值都成立）。

   > 实测：编码参数 **a = 0.1** 写成了 **π/2**，差 **15.7 倍**，F1 虚低 **0.0949**，
   > 四项冒烟测试**全绿**。这是本次影响最大的一处错误，
   > **和"论文没写的东西我猜错了"完全不是一类问题**——
   > 前者是我抄错了白纸黑字，后者才需要猜测和验证。
   > 
  > **推论**：结果对不上时，**先查"论文写明的参数我抄错没有"，再查"论文没写的东西我猜对没有"。**
   > 顺序反了，就会拿着一堆自己编的假设去解释一个抄错的数字。

### 阶段 1 · 取证（动手写代码之前，约 1 小时）

**目标：先搞清楚"这篇论文是不是真的、有没有现成代码、能不能复现"。**

#### 1.1 提取正文

- [ ] **先判版式**：分别提取左右半页，若两侧文本量都在较大一侧的 **30% 以上**，判定为双栏。
- [ ] **双栏**必须按左右列分别 crop 再提取，否则左右栏文字交错。

#### 1.2 ★ 文本提取失败的应急预案（必做）

**先做快速探针**：提取第一页，看是否符合下面任一症状。**症状出现就直接切兜底方案，不要硬读。**

| 症状 | 表现 | 处置 |
|---|---|---|
| **单词粘连** | 空格全丢，`Wedescribeaquantum-assisted...` | ① 视觉模型读渲染页；② 或对渲染页 OCR；③ 正则改用无空格模式 |
| **乱码/二进制** | 提取出 base64 样字符串 | 那是嵌入字体或图像数据，**绕开该区域**，别在全文上跑正则 |
| **无文本层** | 提取结果为空或极少 | 扫描件，直接走 OCR |
| **阅读顺序错乱** | 段落跳来跳去 | 版式判断错了，回到 1.1 |
| **公式/表格错位** | 上下标乱飞 | 用视觉模型读该页，别信文字层 |

> **实测教训**：一篇 PRA 论文文本层空格全丢。后果是关键词搜索大量漏匹配（搜 `data set` 匹配不到 `dataset`），
> 且在全文上跑正则会命中 PDF 里的 base64 字体数据。**必须切视觉，不能硬扛。**

#### 1.3 核实真伪（分两条路）

- [ ] **读 PDF 元数据**，然后按情况走：

| 情况 | 元数据特征 | 验真方式 |
|---|---|---|
| **arXiv 预印本** | `/Creator: arXiv GenPDF`、`/Producer: pikepdf`、有 `/arXivID` 和 `/DOI` | 看这些字段，组合起来伪造不了 |
| **期刊论文原稿** | `/Creator: LaTeX with hyperref`、`/Producer: pdfTeX-*`，**无 arXivID/DOI** | **标题搜索 → 命中期刊名 + 卷期页 + DOI**；再用第二个独立来源交叉印证 |
| **扫描件/未知** | 元数据极少 | 查作者主页 / 机构库 / 学术搜索引擎 |

- [ ] **核版本**：arXiv 的 v1 标题可能与最新版完全不同。**按编号搜，不按标题搜。**

#### 1.4 找代码

- [ ] 全文搜 `github`、`gitlab`、`code available`、`software`、`implementation`、附录。

> 关键词只产生代码线索，零命中也不能证明没有官方实现。核查正文、附录、代码声明和作者提供的项目链接；对候选链接确认可达性、官方归属、论文方法与运行入口。未找到时记录查找范围并按 L2；线索存在但核实失败时标记 `L1-blocked`，保留链接和原因。任务限定官方仓库时，不擅自改成自实现。

##### ★ 找到代码 ≠ 代码能跑：L1 判据要问三件事

> **实测事故（2026-09，第三篇选型）**：一篇论文正文直接给出
> `github.com/emstoudenmire/TNML` —— 按原判据这是标准的 **L1**。
> 十分钟探测之后发现**这条路根本走不通**：
> 仓库**不自带依赖**（源码 `#include "itensor/all.h"`，而 ITensor 要另装）；
> 代码用的是 **ITensor v2 的 API**（v3 已不兼容）；v2 的 `options.mk.sample` 里
> **唯一的 Windows 条目是 Cygwin**（本机是 MinGW），PLATFORM 只支持
> `macos/lapack/mkl/acml`（**全都要 Fortran 可调用的 BLAS/LAPACK**）；
> 构建脚本用 `$(shell uname -s)`；另外还要 libpng16 + png++。
> **名义 L1，实际 L1-blocked。****所以判据扩成三问**：

| 问 | 怎么查 | 不通的后果 |
|---|---|---|
| ① 官方代码是否可用？ | 关键词定位线索，再核对链接可达、官方归属、对应方法和入口 | 未找到 → L2；核实失败 → L1-blocked |
| ② 依赖是否能满足？ | 看依赖版本、可获取性和 README 安装说明；外部依赖本身不算阻断 | 缺失或版本不兼容且无法在任务范围内解决 → L1-blocked |
| ③ 构建系统**在目标平台上可行**吗？ | 核对目标平台、构建说明、依赖 API；在授权执行范围内做最小探测 | 有具体不兼容证据 → L1-blocked；未执行 → 未验证，不能声称成功或失败 |

**做法：先用约十分钟核查三问。** 外部代码只有在任务允许执行时才做最小构建；只读任务记录“运行未验证”。此时间是探测预算，不是可行性结论。

> **性价比**：十分钟拦住了一个可能几小时到几天、且大概率失败的工具链工程。
> **被排除的论文写进 `实测记录`，注明排除理由**——免得下次又选到它。
> **注意与 #26 的一致性**：这条不是"找到代码就悲观"，而是**把"能不能跑"从"开跑之后才发现"
> 提前到"开跑之前"。** L1 分支值得保留，只是判据要更严。

**产出**：真伪结论 + 代码可得性 + **L1 可行性三问的结论** + **文本提取质量判定** + 复现可行性初判。

#### 2.2 ★ 显式区分"哪部分数据用于哪一步"

> **实测教训**：一篇论文写"从训练集 60,000 个元素构建的无监督特征提取器，
> 再定义监督分类器区分 0 和 1"。我一开始把两件事的数据混了——
> 用 0/1 子集（只有 12,665 张）同时建提取器和分类器。
> **正确做法是提取器用全部 60,000 张（10 个数字），只有分类器限于 0 vs 1。**填一张表：

| 模块 | 使用哪些数据 | 是否用标签 |
|---|---|---|
| 无监督 / 预训练模块 | ? | 否 |
| 有监督模块 | ? | 是 |
| 测试 | ? | — |

**这类细节最容易读漏，而且影响很大。**

#### 2.2b ★ 把所有预处理/归一化步骤逐条抄出来核对

> **实测教训**：论文一句话里写着"定义了一个等距变换到**全局归一化的特征空间**"。
> 我把这句话读过去了，**实现里完全没有归一化**。
> 后果：特征范数在两个类别间相差 **5 个数量级**，分类器只读范数、precision 恒等于 1.0，F1 虚低 0.12。
> **补上这一步后 F1 从 0.85 → 0.97。**

**做法**：全文搜这些词——`normaliz*`、`scale`、`standardiz*`、`norm`、`rescal*`、`preprocess`、`whiten`、`clip`、`shift`、`unit`、`divide`、`range`——**每出现一次就抄进表里，逐条对着代码打勾。**

| # | 论文原文（哪一节） | 属于哪一步 | 我的实现 | 状态 |
|---|---|---|---|---|
| 1 | "globally normalized feature space" | 特征提取后 | 无 | ❌ ← 漏了 |
| 2 | "zero-padded to 2^10" | 输入预处理 | 有 | ✅ |
| 3 | … | | | |

**为什么单列这一步**：归一化/缩放**不改变算法结构，只改数值尺度**，所以最容易被当成"细节"跳过，**却最容易造成量级级别的错误**。**而且这类错误有很明显的特征**——见阶段 8「异常信号清单」。

##### ★ 光搜关键词不够：还要做第二张表——「带参数的公式」

> **实测教训（比上面那条更隐蔽）**：
> 论文的编码映射是 $\phi_0=\cos(a\,x/x_{\max})$、$\phi_1=\sin(a\,x/x_{\max})$，
> 参数 **`a = 0.1`**。我抄对了函数形式（cos/sin），**把参数写成了 π/2**——差 15.7 倍。
> 后果：F1 虚低 **0.0949**，而且**所有自检都是绿的**：
> $\cos^2+\sin^2=1$ 对 $a$ 取任何值都成立，所以"编码归一化"这项冒烟测试毫无信息量。
> **`a = 0.1` 在论文里出现三次（散文 / §IV A / Fig. 6 caption），
> 没有一处含 `normaliz`/`preprocess` 之类关键词——关键词表覆盖不到它。**

**做法**：通读时**每一个带参数的公式都单独抄一行**，参数和函数形式分开打勾。

| # | 公式 | 函数形式 | 参数名 | **参数值** | 论文出处 | 我的实现 | 状态 |
|---|---|---|---|---|---|---|---|
| 1 | 编码映射 Eq.(5) | ✅ cos/sin | `a` | **0.1**（O(0.1)） | 散文 + §IV A + Fig.6 caption | π/2 | ❌ ← 差 15.7 倍 |
| 2 | 截断判据 | ✅ | `ε` | 2×10⁻⁴ | §III | 2e-4 | ✅ |
| 3 | … | | | | | | |

**判据**：抄的时候问自己一句——**"如果我把这个参数改成 10 倍，指标会不会变？"** 会变，就说明它是实质参数，必须抄准。**顺带一条**：这类错误会让"可解释诊断量"暴露出数量级级别的矛盾。本次是 `min_chi`（论文判据要求的最小键维）在某一层从 1 跳到 **4095**，而论文声称 χ=79 就够——**差两个数量级**。看到这种矛盾就该立刻回去抄参数，而不是调超参。

##### ★ 第三张表——训练协议三件套（batch / 学习率调度 / epoch 数）

> **实测教训**：第三篇的 dropout 复现，卡了我最久的就是"学不动还是学得慢"。
> 根因翻出来只有一个：**论文全文 `batch` 零命中**——它压根没写批次大小，
> 而我默认用了 4096（14 步/epoch）。dropout 在这个批次下贴随机永不学；
> 换 batch=512（108 步/epoch）立刻收敛到 89.3%。
> 同样，"an **initial** learning rate of α=0.001"里的 "initial" 暗示有衰减调度，**调度没写**。

**做法**：拆解阶段就把这三样单独抄成一行，**没写明的直接标「未声明」并当成警报**，不要默默用默认值：

| 项 | 论文原文 | 是否写明 | 我的取值 |
|---|---|---|---|
| batch size | （搜 `batch`/`mini-batch`/`stochastic`/`shuffle`） | 常 **零命中** | 先实测几档，别拍 4096 |
| 学习率衰减 | "an **initial** learning rate" | 常只有 "initial" | 默认常数，但要标记 |
| epoch 数 | 图 5/6 的横轴 | 常在图里 | 按图外推 |

**为什么单列**：这三样**决定"每 epoch 多少步、总共多少步"**，而"学不动"和"学得慢"、
"欠拟合"和"没跑够"，都只能靠这个量来区分。它们和归一化、公式参数一样是"数值尺度"类细节，
却比那两类更难靠搜索兜住——**因为论文经常一个字都不写。**

#### 2.3 ★ 找"靶子数字"——不要假设论文有主表

| 结果形式 | 取靶子的做法 |
|---|---|
| **有主表** | 照抄主表作为靶子 |
| **没表，全在图里** | ① **先在正文里捞关键数字**；② 正文没有的，再用视觉模型读图（**方法见下**）；③ 必要时数字化曲线 |
| **只有定性描述** | 靶子只能是"趋势"或"量级"，别硬凑精确数字 |

> **实测教训**：一篇 PRA 论文全文 `TABLE` **零命中**，15 张图承载全部结果。
> 但正文里明写了关键值（"ε=2×10⁻⁴ 时键维 79 足以得到平均 F1 = 0.9985"）——**先捞正文再看图，省得多。**

##### ★ 图上的数不能当数据用——判"不可检验"是合法结论

**规则**：图只能用于**定性趋势对照**；**任何进入表格的数字都必须是文字给出的。**

> **实测事故**：想从 Fig. 6（10 类 F1 vs 键维）取出论文的曲线值来对照。
> 同一张图**两次读数互相矛盾**（χ≈80 处一次读成 0.80、一次读成 0.91），
> 第三次视觉模型**开始编造**（先说看不了图，随后给出一串假读数）。
> **最终处置：记录尝试过程，把该图对应的结论判为「不可检验」，只做定性趋势对照。**
>
> 论文 15 张图里，只有 4 个数字能进对照表——**其余 11 张的量值对照根本不做**。
> 这不是失败：**"不可检验"和"没做到"是两回事，前者要显式写出来。**

##### ★ 全文结果都在图里时，改做"内部对照"

既然拿不到论文的曲线，就自己造一个**有区分力的对照**：**同维度经典基线**（如 PCA-K，K = 你的特征维数）。它回答的是"**这个方法是否胜过同等宽度的经典做法**"——这正是论文图想表达的东西。

> 实测：这么做之后得到 TTN 0.8782 vs PCA-81 0.8595（+0.0187，6.9σ），
> 以及**差距随键维单调增长、经典基线饱和**——**论文 Fig. 6 的定性论断被独立验证了**，
> 而这个结论**不依赖能否读出论文曲线的具体数值**。

#### 2.4 把"论文没写的东西"分成四类

| 类型 | 处理方式 |

| **可以扫描的**（如某超参） | 在已授权候选范围和预算内扫描；只要求方案时只列方案 |

#### 3.1 ★ 顺便把阶段 5 的"数值对照"做掉

**这是实测发现的最高性价比协同**——阶段 3 和阶段 5 不该分开做。

> 写 smoke test 时，**故意用另一条代码路径**再实现一遍核心计算——
> 比如高效实现按分量算，参考实现把整个中间张量显式建出来再算。
> 两者一对，**既验证了 smoke test 本身，又直接产出了阶段 5 的"数值对照"**。

#### 3.2 张量/网络类方法的调试提示

**这类代码的 bug 90% 是轴与维度的错位**，不是算法错：
- 每一步都打印 **shape** 和 **sum**，比读报错快得多
- 特别注意**分组后的维度**：$N$ 个 site 两两配对后是 $N/2$ 个轴、每轴 $d^2$ 维
- 注意**同一算子连续作用多次**时，每次作用的是哪个轴（第一次作用后末轴已变）

**产出**：可运行的 smoke test + **参考实现** + 对工具链的信心。

#### 4.1 ★ 判据方向性自检（实测踩过的坑）

**凡是要实现"带阈值 / 带判据"的算法，先问一句：这个判据随参数增大是变松还是变紧？**

> **实测教训**：White 规则的截断判据 $1-\frac{\sum_{\alpha\le\chi}p_\alpha}{\sum_\alpha p_\alpha}\le\varepsilon$
> 的含义是"**丢弃**的重量不超过 ε"，而丢弃重量**随 χ 增大而减小**——
> 也就是说判据越大的 χ 越容易满足。
> 我把循环写成"不满足就**减少** keep"，这是越减越不满足，**必然一路减到 1**。
>
> 后果：$\chi$ 全程塌成 1，指标腰斩。**最危险的是它看起来像"论文的截断真的很激进"——
> 差点被我当成论文的性质记下来。****这类错误不报错，只静默给出错误结果，而且极易被误读成"论文的方法就是这么差"。**

#### 4.2 ★ 资源规划要实测驱动

**先在小规模跑通并打印每步实际内存，再外推。**

> **实测教训**：我按"两 site 密度矩阵是 $6241^2$"静态估算峰值约 1 GB，
> **实测 10.3 GB**。真凶不是密度矩阵，是**状态应用那一步**一次性建出的
> `(10000, 16, 6241)` 中间数组 = 4 GB——我完全漏了。
>
> 分块后 10.3 GB → 1.7 GB，耗时不变。

**要点**：

- 分块时注意**乘数**：中间数组形状常是 `(chunk × n_units, d²)`，别只按 `chunk` 估
- 让分块大小由**内存预算反推**，而不是拍一个固定值
- 每层打印 **耗时 + 峰值 RSS**

##### 4.2b ★ 优化之前先剖面，不要从"调用次数多"推到"这里慢"

**把实测时间拆到「前向 / 反向 / 最大的那个中间量」的粒度，再决定改哪里。**

> **实测教训（第三次复现）**：6.59 s/step 太慢，我从"每个前向有 85 次独立的
> autograd-traceable einsum 调用"推断瓶颈是 Python 调用开销，
> 于是把逐节点循环改成整层堆叠（85 次 → 8 次）。**结果反而更慢（7.17 s/step）。**
>
> 剖面一测才看清：**前向 2.0 s、反向 5.3 s**，而 layer 0 的 ψ 中间量本身就有
> `(4096, 64, 4, 64)` = **6710 万个 complex = 1.07 GB**——与调用次数毫无关系。
>
> 真正拿到 **3.9×** 的那一步是**把 einsum 换成 batched matmul**（见工程坑 15），
> 而我猜的那个改动**一次都没命中**。见附录 B 第 30 条。

**要点**：

- 剖面脚本**单独写**，不要在生产代码里插计时代码
- 同时量 **时间** 和 **最大中间量的元素数**——后者常常就是前者的解释
- **猜错的改动要原地记下来**（这次把 6.59 → 7.17 的退步一并写进档案），  否则下次还会照同一个直觉再猜一遍

#### 4.3 ★ 暴露诊断量（原则 5 的落地）

**在关键中间步骤打印一个可解释的量。**

> **实测例**：TTN 每层打印两个数——
> - `captured`：截断后**保留了多少概率重量**
> - `min_chi`：**满足论文自己的 ε 判据需要多大 χ**

>
> 结果一眼看出问题：论文说 χ=79 足够，而我的实现需要 χ≈700~4200；
> χ=79 时丢掉了 **20%+** 的重量。**这把"指标差 0.15"直接定位到了具体环节，省掉几小时瞎调。**

##### 4.3b ★ 诊断量要**按类别、按层**拆开看

**同一个诊断量，只报总体均值会掩盖问题；按类别/按层拆开，问题自己会浮出来。**

> **实测例（同一个复现，第二次才发现的 bug）**：
> 特征范数只报总体均值是 0.25，看不出异常。
> 把它**按类别拆开、按层追踪**：
>
> | 层 | 真0 | 真1 |
> |---|---|---|
> | L4 | 2.456 | 2.775 |
> | L6 | 0.557 | 1.048 |
> | **L7** | **8.6e-06** | **0.475** |
>
> **两个类别在末层相差 5 个数量级**——一眼就能看出是哪一层出的问题、坏在哪一类上。
> 只报总均值的话，这个 bug 会一直藏着。

**建议**：任何中间量都同时打印 **总体均值 + 分类别均值 + 逐层（或逐阶段）值**。多打两行日志的成本，远低于事后重新排查。

##### 4.3c ★ 可视化判断：先检查显示范围，再换成数字

**任何"看起来像 / 不像"的判断，都要先做两件事：**
1. **检查显示范围**。值域到 4.14 的图按 [0,1] 截断显示，会几乎全饱和——   **你看到的不是"数据差"，而是"显示差"。**
2. **把"像不像"换成一个数字**（相关系数、类间距离、有序性指标）。

> **实测事故**：把 TTN 特征向量 fine-grain 回数据尺度的特征图，值域到 **4.14**，
> 而真实像素在 [0,1]，我按 `vmin=0, vmax=1` 显示，绝大部分被压成饱和白。
> 于是**把一次成功的复现判定成"像噪声、未复现"，还写进了报告**。
> 改成每个子图各自拉伸对比度后，环和笔画清清楚楚。
> 换成"与类别平均图的相关系数"后立刻可判：**0.66（实测）vs 0.77（单张真实图 vs 其类别平均图）**。
>
> **两个附带教训**：
> - **看图的多模态模型也会被坏的显示骗**。它说"是噪声"没错，错的是喂给它的图。
> - **不要把看图模型的数值读数当数据**。同一个图我得到过互相矛盾的两次读数

>   （0.80 与 0.91），第三次模型开始编造。
>   **图上的数只能用于定性趋势，不能进表格。**

##### 4.3d ★ 测"两个近乎退化的量之差"之前，先做记账稳定性检验

**要测 $A-B$ 时，先问两个问题：**① $A$ 和 $B$ 本身相差多少？② 我对它俩的处理，有没有哪怕一点点不对称？**若"两者相对差"与"记账注入的扰动"同量级，这个差不可测，任何符号都不能报。**

> **实测事故**：要测 $W_1-W_0$ 的中心/边缘结构。
> 两个权重向量**相对差只有 2.3e-4**，而"各自归一化到单位长度"这**一个选择单独就注入 2.15e-4**
> ——**和信号一样大**。同一个统计量只因归一化方式不同就从 **+0.0457 变成 +0.0239**（差 90%）；
> 再做缩放扫描，符号在 **+0.061 到 −0.003** 之间来回穿零，c≥5 时全部饱和、相关系数无定义。
> **我最初报的"方向与论文相反"是过度解读，实为不可分辨。**
>
> **做法**：固定判据（看结果之前写死）→ 换 ≥2 种记账方式各算一遍 →
> 至少再做一次 bootstrap 或分折，看符号是否稳定。**符号不稳，就记"无法判断"。**

**产出**：可复现的完整代码 + 每个猜测带标注 + **分类别/分层的诊断量输出**。

### 阶段 5 · 自证正确（论文没给代码时是关键）

执行本阶段时使用随包 `references/evidence-and-delivery.md` 第 1 节标注检查覆盖范围；有断点恢复时按第 2 节验证恢复语义。仅通过端点或归一化检查不能排除输入表示错误。

| 校验 | 做法 | 通过标准 | 是否总能做 |
|---|---|---|---|
| **数值对照** | 核心算法 vs 一个慢但显然正确的实现 | 误差 < 1e-12 | ✅ 几乎总能 |
| **梯度校验** | 解析梯度 vs 中心差分 | 误差 < 1e-8 | ✅ 有可训练参数就能做 |
| **等价性对照** | 找一个"你的实现必须退化成 X"的边界情况 | 逐位相等 | ⚠️ **不一定存在** |
| **不变式对照** | 带约束的优化器：每步检查约束是否被保持 + 算符公理 | 机器精度 | ✅ 有约束就能做 |

##### 5.0 ★ 写"数值对照"的暴力参考实现时，有三条硬要求

> 这是本次实测里**最有价值的一件工具**：它一个实现抓出了**两个真 bug**，
> 而且两个都是"大部分输入下结果正确"的类型——抽样检查极可能全部漏掉。

1. **在【全部】输入上对，不是抽样对。**

   > bug 1：**LCA 取错层**（取了"祖先相同的**最大**层"，但一旦重合后续祖先全都相同，
   > 于是 sibling 被误判成在根相遇）。它**只在两个 site 同属一个父节点时才错**。
   > 随便抽几个 pair 看，很可能全抽到对的那批。

2. **即使生产代码是实数，也要跑一个【复数】测试用例。**

   > bug 2：**共轭加错了位置**。实数下 `conj` 是恒等，bug 完全不显形；
   > 只有复数随机树才暴露。而 trace 恰好还是对的，所以连"守恒量检查"也抓不到。

3. **让新代码有一条"退化回旧代码"的开关。**

   > 混合态通路必须要有一条检查：**什么都不缺时，它必须逐位等于已验证的纯态通路**。
   > 实测两者预测 100% 一致。**这条不过，后面所有部分数据的结果都没有意义。**
   > 做法：给新实现留一个能让它退化成旧实现的参数（这里是"缺失集合为空"）。

##### 5.0b ★ 约束优化器：开跑之前先验三条不变量

**加约束的优化器最容易在三处静默出错，而且错了照样收敛、代价照样下降。**

| 不变量 | 一行断言 | 本次实测 |
|---|---|---|
| 投影**确实落在切空间** | $\lVert W^\intercal P+P^\intercal W\rVert=0$ | 5.4e-17 |
| 约束**每一步都保持** | $\lVert W^\intercal W-I\rVert$ | 2.2e-16 |
| retraction **满足公理** $R_W(0)=W$ | $\lVert R_W(0)-W\rVert=0$ | 2.2e-16 |

> **第三条最容易被忽略**：QR retraction 的符号处理若写错，$R_W(0)$ 可能返回 $-W$——
> **优化照跑、代价照降，但收敛到的东西不对。**
> **这三条不通过，后面 500 个 epoch 的数字一个都不算数。**

#### 5.1 找等价性对照的思路

- **参数取极端值**时，方法是否退化成某个更简单的方法？

  > 实测例：TT 秩取到最大键维（1024 维 → r=32）时 TT 无损 ⟹ Pre-TT **必须逐位等于振幅编码**。
  > 10 个种子实测配对差恒为 0，把正确性从"看起来对"升级成"**证明是对的**"。

- **关掉某个模块**时，是否回到 baseline？
- **小规模特例**是否与解析解一致？

#### 5.2 找不到就诚实标注

退而求其次：做**量纲/边界/守恒量检查**，或用已知答案的合成样例端到端验证。**并在报告里明确写出"本条校验缺失"**——这比假装做了强。

> **实测补充**：树张量网络就**没有** TT 那种干净的键维上界（树结构下上界依赖拓扑），
> 等价性对照的候选（"χ 取到不截断上限时应无损"）**未能构造出来**。

**产出**：校验脚本 + 通过记录；**缺失项显式标注**。

#### 6.1 ★ 结果对不上时的判断流程

> **这是全流程最关键的分叉：是我的实现不匹配，还是论文有问题？**

```text
结果对不上
   │
   ├─ ★ 预算与错误证据判据
   │     先查报错、有限值、输入规格和更新链路；有具体错误证据就诊断修复。
   │     仅证据不足以区分慢与错时，在授权预算内选一个因素做受控诊断：
   │       ① 更长 epoch（本次 40→400 才翻案）
   │       ② 更小 batch（每 epoch 更多更新；本次 batch 4096→512 让 dropout 起死回生）
   │       ③ 更高 lr（本次 lr 1e-3→1e-2 让 loss 开始动）
   │     无需三项试遍；仍贴随机不能单独证明有 bug，预算不足或证据不足记“无法判断”。
   │
   ├─ ★ 前置三问（先做，别急着改实现）
   │     │
   │     ├─ ① 输入本身可分吗？    → 看类间差距。差 1 个数量级 → 数据没问题，继续往下
   │     │                          （实测：HAR 动态/静态类的 ‖加速度‖ 差 15 倍，数据是好的）
   │     ├─ ② 换一个"已知更好"的表示，同一套代码能上去吗？
   │     │     → 能上去 = **你的代码没坏，是输入表示不对**
   │     │       （实测：把两条范数序列换成 UCI 561 维工程特征，F1 从 0.35 → 0.9649）
   │     └─ ③ 用不依赖模型假设的方法（k-NN 等）测这个表示的**表达上限**
   │           → 上限本身就低于论文值 = 再怎么调模型也没用
   │             （实测：两条范数序列的 k-NN 上限只有 0.57，论文要 0.96）
   │
   ├─ 诊断量（阶段 4.3）能否定位到具体环节？
   │     │
   │     ├─ 能 → 是哪个环节？
   │     │        ├─ ★ **论文写明过的参数值抄错了吗？**（阶段 2.2b 公式参数表）→ 先查这个
   │     │        ├─ 前处理/数据分工错 → 修，重跑
   │     │        ├─ 结构/拓扑假设错   → 列出候选结构，逐一验证
   │     │        └─ 判据/阈值错       → 回到 4.1 做方向性自检
   │     │
   │     └─ 不能 → 逐项做受控对照，把差异隔离到单一变量
   │
   └─ 最终仍有差异且无法归因 →
         → 结论落入"无法判断"级，不是"推翻论文"
```

#### ★ 实测例（2026-09-13 重写，旧版教错了方向）

>
> **现象**：TTN 的 0-vs-1 测试 F1 = 0.9036，论文是 0.9985。
>
> **旧版结论（错的）**：诊断量显示 χ=79 时丢掉 22% 的重量，而论文说 χ=79 足够
> ⟹ "是我的**结构假设**与论文不符（共享等距 + 1D 链 vs per-pair + 2D 树）"
> ⟹ "结构未对齐，无法评价论文"。
>
> **旧版错在哪**：我据此改了两处结构，**其中一处（1D 链 vs 2D 树）是我凭空造出来的伪假设**——
> 行主序数据上的一维二叉树，前 log₂16=4 层天然就在行内配对、后 4 层合并整行，
> **本来就是论文说的"先行后列"**；另一处（per-pair 等距）在固定 χ 下**对指标毫无影响**
> （实测两者都 0.9982）。**两处结构改动都不是原因，白白花掉两轮实验。**
>
> **真实原因**：论文 Eq. (5) 的编码参数是 **a = 0.1**，我写成了 **π/2**，**差 15.7 倍**。
> 改回来之后 F1 从 0.9036 → 0.9974，诊断量同步塌回正常
> （`min_chi` 在 L4 从 **4095 → 1**）。
>
> **所以正确顺序是**：诊断量既然指向"论文的判据在 χ=79 下根本不成立"，
> 而这个矛盾**差两个数量级**，第一个该查的就是
> **"论文写明的参数，我有没有抄错"**，而不是"论文没写明的结构，我猜得对不对"。
> 见核心原则 9（带参数的公式必须逐条抄表核对）。

#### 6.2 统计检验的坑

- 并行框架返回的顺序是**完成顺序**，不是输入顺序。做配对检验前必须按种子重排。
- 论文的"耗时"往往单次运行无误差棒——复现时各跑一遍，看极差是不是和运行噪声一个量级。

**产出**：带误差棒的对比表 + 显著性结论 + **差异归因表**。

#### 8.1 ★ 异常信号清单（逐条打勾）

**指标"好得不自然"和"差得离谱"一样值得追查。** 出现下列任一现象，停下来查：

| 异常信号 | 可能的含义 |
|---|---|
| **某个指标精确等于边界值**（precision = 1.0000、recall = 1.0000、acc = 100%） | **分类器退化**——只在一个方向上预测 |
| 指标好得超出常识（如小数据上 F1 > 0.99） | 数据泄漏 / 标签泄漏 / 划分错误 |
| 混淆矩阵某一行或列**全为 0** | 同上，分类器塌向单一类别 |
| 中间量的**方差接近 0** | 计算被冻结 / 梯度断裂 / 变量没更新 |
| 某个中间量**出现精确 0 或 nan/inf** | 数值下溢、除零、空张量 |
| 训练集和测试集指标**几乎相同**且都很好 | 划分重复、或测试集泄漏进训练 |
| 结果对超参**完全不敏感** | 那个超参实际没接进计算图 |
| 指标**好了一个数量级**却又说不清为什么 | 多半是 bug，不是突破 |
| **某个自检对目标参数完全不敏感** | **自检本身失效**——它在该参数取任何值时都通过（见下） |
| **两个被比较的量本身几乎相同** | 它们之差不可测，符号会被记账选择支配（见 4.3d） |

> **实测教训（第一条）**：`precision` 在二分类任务上**精确等于 1.0000** 就是那根线头。
> 顺着它查下去，发现了漏掉特征归一化、以及由此造成的虚假 0.12 差距。
>
> **实测教训（新增两条）**：
> - **"编码归一化"这项冒烟测试对编码参数 *a* 零信息量**——

>   $\cos^2+\sin^2=1$ 对 *a* 取任何值都成立。我把 *a* 写成 π/2（差 15.7 倍），
>   四项自检**全是绿的**。**检查必须能对错误的实现失败**，
>   否则它只是让人安心，不产生信息。设计检查时问一句：**"我把这个参数改错，它会红吗？"**
> - **两个权重向量相对差只有 2.3e-4**，而记账选择单独就注入 2.15e-4——

>   这时任何"哪个更大"的结论都由记账决定，不由数据决定。

**产出**：`verify_results.py`（一键重算）+ 勘误记录 + 敏感性结论 + **异常信号检查记录**。

#### 9.0 ★ 交付前：再做一遍系统复查（原则 8 的落地）

> **实测教训**：这是一次"完成后复查"抓出的最大一处错误。

**复查清单**：

- [ ] **逐条比对论文原文里的预处理/归一化/缩放**（阶段 2.2b 关键词表）——**最容易漏、影响最大**
- [ ] **逐条比对论文里每一个"带参数的公式"的参数值**（阶段 2.2b 公式参数表）——**关键词搜不到，只能人抄**

- [ ] **诊断量按类别、按层再打一次**（4.3b）——**看有没有数量级级别的矛盾**（本次是 `min_chi` 从 1 跳到 4095）
- [ ] **把每个"论文没写、我自己猜的"参数再确认一遍**理由是否成立——      ★ 尤其要问：**"我怀疑的这个结构差异，是真的存在，还是我自己读错了？"**      （本次我凭空造出"1D 链 vs 2D 树"这个伪假设，白花两轮实验）
- [ ] **★ 拆解表里每个标为「可以扫描 / 缺失」的参数，逐条核对：扫描真的做了吗？代码里那个默认值是从哪来的？**      ★ 判据：**这个默认值必须是拆解表列出的候选之一**，不然就说明我当时悄悄换了操作。

      > 实测教训：论文写 "we **downsize/rescale** each image to 16×16"，拆解表**正确**列出了
      > "块平均 / 双线性 / 双三次，逐条实测"，**但代码里放的是 `X[:, :16, :16]` 左上角裁剪**——

      > **它结构上不可能发现输入表示本身选错了**。（附录 B 第 31 条）

- [ ] **做一次"去掉这个方法"的基线**——不用论文的方法，能不能得到同样的数字？
- [ ] **负对照用的指标对不对**——类别不平衡时 F1 的随机基线不是 0.5，改用平衡准确率/MCC
- [ ] **每个"意外发现"都做过稳定性检验了吗？**（4.3c 显示范围 / 4.3d 记账稳定性）      —— 没有的话，降级成"无法判断"，别写进结论

#### 9.1 结论分三级

| 级别 | 判据 | 措辞 |
|---|---|---|
| **能推翻** | 与论文具体设定无关（如算术、与实现选择无关的对照） | "该主张不成立" |
| **不能推翻** | 依赖未知设定，或只在某些设定下成立 | "在 X 设定下成立，在 Y 下不成立" |
| **无法判断** | 没做、或结构未对齐、或数据不可得 | "**结构未对齐，无法据此评价**" |

> **"无法判断"不是失败。** 实测中 TTN 那篇的可解释性一项就落在这里——
> 如果强行报成"论文报得太乐观"，那是**用错误的自信掩盖了自己的实现问题**。
>
> **升级到更高级别需要证据，不是需要态度。** 本次把一项从"未做"升级到
> "已复现"靠的是：三组数字全部落在论文值附近（差 0.0007~0.003）+
> 两条定性论断逐条实测 + 超参扫描证明不依赖调参。**缺任何一条都只能停在下一级。**

#### 9.2 措辞要准，而且**不利结果必须一并报出**

本文的准确表述例：**"数字对得上，归因错了"**，而不是"论文被推翻"。**★ 三条硬性要求：**
1. **不要说"论文错了"，要说"我没复现出来"。** 未复现的第一嫌疑永远是自己，   除非有与实现选择无关的对照（那才够"能推翻"级）。
2. **对自己不利的结果，必须写进同一份报告，不能只留有利的那条。**

   > 实测：MNIST 10 类上 TTN 明显赢同维度经典投影（+0.0187，6.9σ）；
   > **HAR 上同一套方法却输给朴素线性基线**（0.9253 vs 0.9637），对同维度 PCA 也略输。
   > **两条都写进报告了。** 只报前者，等于把"方法普遍有效"这个我并没有证据的结论
   > 塞给了读者。

3. **把"数字对得上"和"方法被验证"分开说。** 前者只说明该指标接近，不能单独证明实现正确；后者需要区分力证据（去掉方法的基线 + 同维度对照）。

> **给导师的口径**：留解释权给对方。
> 不说"论文被推翻"，说"**这一项我没复现出来，可能是我这边的输入表示没确定**"；
> 不说"论文是对的"，说"**核心主张复现通过，但性能主张只在 MNIST 上成立，HAR 上我没有证据**"。

#### 9.4 先核对逐实验对照表

从阶段 2 的实验清单开始，为本次范围内的每个实验分配稳定编号 E01、E02……。未执行、失败和不利结果也必须占一行；范围外实验另列“未覆盖范围”，不默认为已完成。先填表并核对证据，再新增读者摘要。已有报告布局可以沿用，但必须包含以下信息。

| 实验编号与目的 | 论文结果及出处 | 本次结果及证据 | 比较条件与差异 | 执行状态 | 当前判断 |
|---|---|---|---|---|---|
| E01：用一句话说明验证什么 | 指标、单位；论文版本、页码、图表编号 | 指标、单位；原始结果文件链接及字段，运行记录链接 | 数据划分、预处理、模型、训练预算、指标定义、种子数是否对齐；数值差异 | 未执行／运行失败／已完成 | 支持／部分支持／不支持／证据不足，并写明具体主张与适用范围 |

填写规则：

- 论文值必须回查原文；本次值必须回查实际结果。旧报告仅提供检索线索，不能作为已经复核的证据。无法取得原文或结果文件时填“未核实”并列出缺失项，不凭记忆补数。
- 相同实验存在多组配置时分行或用 E01a、E01b 区分。改参数、换数据或增加预算得到的结果标注“修改配置实验”，不与论文原配置混写。
- 只有指标定义、单位和评价对象一致时才计算数值差；统一写“本次值 − 论文值”。准确率从百分数相减得到的是“百分点”。条件不一致时标注“仅供参考”，不能据此判定复现成功；无法比较时填“不计算”。
- 没有预先确定的验收容差，不因“只差 1 点”自动判成功。单种子结果不推断稳定性，不把差距直接解释为随机噪声。执行完成只说明运行结束，不自动升级结论。
- “支持／不支持”必须限定到具体主张与已核对条件；条件未知、证据缺失时填“证据不足”。这不等于阶段 9.1 的“能推翻”。
- 论文原图和本次结果图可在对应实验下左右并排，分别链接出处和原始数据。原图、按论文数据重绘、图片估读必须明确区分；缺图时如实写缺失原因，不生成替代证据。视觉相似不能单独作为成功判据。
- 表格保持简洁，长命令、完整配置和诊断过程放在链接指向的证据中。不要把整个日志塞进单元格。

#### 9.5 保留原有总结，另增读者摘要

原有总结的内容、结构和生成要求保持不变；本步骤只新增摘要，不替换、删减、搬移或改写原总结，也不覆盖已有的 `00-交差说明.md`。在 `01-复现报告.md` 的标题和论文信息之后、原正文之前，增加独立的“读者摘要”章节。重复执行时只更新该摘要章节，避免重复追加。写作顺序是先核对表再生成摘要，读者可以先读摘要，再查看原有总结及实验对照表。

按下列四段组织，每段一至三句，使用普通中文；关键术语首次出现时补充简短解释，不要求读者先看日志或再交给 AI 翻译：

1. **研究问题与本次范围**：论文想验证什么，本次实际检查了哪些实验；只做启动检查时直接说明。
2. **主要结果**：引用实验编号，写已核实结果及其含义。区分指标接近、趋势一致和论文原配置复现，不能互相替代。
3. **限制与未决项**：哪些实验未完成，哪些条件不同，哪些原因尚未验证；推测单独标注“待验证解释”。
4. **下一步**：列出最影响判断的一至三项工作，每项对应缺失证据；尚未执行的工作不得写成已完成。

示例（虚构数据，仅说明表达方式，不得复制为实际结果）：

> 本次检查模型在图像分类任务上的表现，完成了 E01，E02 尚未执行。
> E01 的测试准确率为 88%，论文报告为 90%，本次低 2 个百分点。由于本次训练轮数少于论文，这只是不同训练预算下的观察，尚不能判断论文原设置能否复现。
> 目前没有证据确定差距原因，也没有多次运行结果支持稳定性判断。
> 下一步是在已授权预算内对齐训练设置，再核对 E01；E02 仍列为未执行。

交付前逐项核对：

- [ ] 摘要中的每个数字、判断和已确认原因都能定位到对照表及其证据；摘要中无来源内容删除或标为未核实。
- [ ] 原有总结保持原样。摘要与核实后的对照表一致；若与原总结或正文冲突，在摘要内增加“与原报告的分歧”说明，列出实验编号、原说法、当前证据及判断，不能沿用错误结论，也不能静默修改原文。
- [ ] 未把改配置后的接近结果写成原配置复现，未把缺失证据写成论文错误，未隐藏失败项。
- [ ] 读者只看摘要就能回答“研究什么、实际做了什么、结果说明什么、还不能判断什么”；读对照表能找到依据。

核对失败时先修正对照表，再重新生成摘要，原有总结不动。无法补齐证据时保留“证据不足”，不要为了报告完整而补写结论。

#### 9.6 交付一致性与证据范围

按随包 `references/evidence-and-delivery.md` 第 4–6 节核对摘要、图注、结果字段和 run ID。把执行状态、实现检查和论文主张支持程度分开；检查全通过不能直接写成全部复现。

结果变更后重新生成受影响的图和新报告部分，保留原总结。打包时使用随包 `scripts/verify_delivery.py` 比较认可的交付暂存目录与归档；它只验证文件一致性，不替代图内容审阅、数据来源追踪或科学结论核验。

## 五、工程坑清单

#### 文本与 PDF

1. **文本层空格丢失**：后果是关键词漏匹配、正则会命中 PDF 里的 base64 字体数据。**必须切视觉/OCR。**
2. **在全文上跑正则会被嵌入数据污染**：先定位"正文页范围"，再在正文上搜。
3. **PowerShell `Tee-Object` 写 UTF-16**：读日志要处理编码，否则正则全不匹配。
4. **控制字符会让阅读工具把文本文件误判为二进制**：落盘后清理 `[\x00-\x08\x0b\x0c\x0e-\x1f]`。

#### 数值与并行

5. **并行 + 大矩阵 → BLAS 线程超订**：**必须在 shell 层**设 `OMP_NUM_THREADS=1`；在进程内设已经晚了。不设实测慢十倍以上。
6. **Python 缓冲输出**：后台重定向到文件时，print 不带 `flush=True` 看不到进度。
7. **`imap_unordered` 返回完成顺序**：配对检验前必须按种子重排。
8. **内存估算要看"乘数"**：中间数组常是 `(chunk × n_units, d²)`，别只按 chunk 估。
9. **同名函数被后定义覆盖**：`rss_mb` 被文件后部的旧版覆盖，静默返回 nan。**改完代码搜一遍函数名。**
10. **`import resource` 是 Unix-only**：Windows 上直接 ImportError，要用 `GetProcessMemoryInfo`（注意设 `argtypes/restype`，否则伪句柄被符号扩展导致调用失败返回 0）。

#### 深度学习 / 框架

11. **PennyLane 版本 API 差异**：`qml.grad` 的 `argnum` 新版才支持。
12. **autograd 里混用 numpy 会静默断梯度**：loss 里要用 `autograd.numpy`，否则训不动还不报错。    **本次新踩到一个更细的版本**：连 `np.real(ArrayBox)` 都会断——它不走 `anp.real`，    而是取底层值把追踪切断。症状是**梯度精确全零、有限差分却完全正常**，    而 autograd 只给一条 `UserWarning: Output seems independent of input`。    实测 `autograd.grad(lambda v: np.real(m.loss_on_vec(v, ...)))(vec)` 得 \|g\| **= 0.0**（894 个分量全零），    只把 `np.real` 换成 `anp.real` 立刻变成 **3.98e+02**。    **凡是要被求导的包装函数，一律用 `anp.real`。** 见附录 B 第 28 条。
13. **`fetch_openml` 拉 MNIST 极慢**：直接下 idx 文件，20 秒搞定。
14. **`np.einsum` 会拒绝一部分"纸面上合法"的下标**：    当两个操作数共享的**非收缩**指标与各自独有的自由指标**交错**时，    numpy 走广播路径并抛 `operands could not be broadcast together`。    实测 `'inkm,isnm->isnk'`（AL `(16,4,2,2)` × blk `(5,16,4,2)`）**纯 numpy 也失败**，与 autograd 无关。    能通过的规律是：**共享自由指标在两个操作数里同序排最前、各自独有的指标居中、收缩指标排最后**。
15. **`c_einsum` 是朴素嵌套循环，比 BLAS 慢一个量级**：凡能改写成 batched matmul 的收缩就别用 einsum。    实测（S=4096, b=4, r=64）：Eq.(13a) **einsum 0.68 s vs matmul 0.16 s（4.3×）**，    Eq.(13b) **0.45 s vs 0.028 s（16×）**，两者结果只差 **1e-14**（同一次求和的结合顺序）。    整条训练步 **6.59 s → 1.71 s（3.9×）**。
16. **把基准脚本里的表达式抄进生产代码时，要重新核对每个变量的当前形状**：    基准脚本里 `ATt` 已经是"预先转置过"的 `(n,o,r)`，所以那句 `swapaxes(ATt,-1,-2)` 是对的；    照抄进生产代码时 `AT` 本来就是 `(n,k,o)`，这个 swapaxes 就多余了。    症状是 `matmul: Input operand 1 has a mismatch in its core dimension 0`。
17. **GPU 存在但后端没装，不等于能用**：本机有 RTX 5060（8 GB），    但 `torch/tensorflow/jax` 一个都没有，`import` 全是 `ModuleNotFoundError`。    **资源规划要先探测，不要看到 `nvidia-smi` 就按 GPU 算时间。**

#### Windows / PowerShell / 编码（本次实测新踩）

18. **PowerShell 不支持 heredoc**（`python - <<'EOF'` 会报"重定向运算符保留"）：
    把脚本写成临时 `.py` 文件再跑，或用 `python -c "..."` 单行。**本次在这上面白花了两轮。**
19. **GBK 控制台会因非 ASCII 字符抛 `UnicodeEncodeError`**：    中文输出、零宽空格（`\u200b`）、特殊数学符号都可能触发。    **含中文输出的脚本一律先设 `$env:PYTHONIOENCODING="utf-8"`。**
20. **日志编码在同一批实验里可能不统一**：本次 `01`–`08` 号是 UTF-16（PowerShell 重定向），    `09` 号之后是 UTF-8。**所有读日志的脚本都要带一个 `read_any` 兜住两种编码**，    否则正则静默零匹配。
21. **matplotlib 缺字形时不报错，只在 stderr 提示**：    `⟹`（U+27F9）这类符号会渲染成方框。用 `2>&1 | Select-String -NotMatch 'glyph'`    把噪声滤掉，但**要确认它滤掉的是噪声**——中文缺字形就得换字体，不能滤。
22. **★ 不要用 shell 文本替换就地改方法论文档**：`Set-Content -NoNewline` 会把整个文件压成一行、
    `>` 重定向写 UTF-16。**改大文件前先留副本、改完立即验行数/结构。**
    本次用 `(Get-Content ...) -replace ... | Set-Content -NoNewline` 把 `复现工作流.md`
    从 1020 行压成了 1 行，内容没丢但换行全没了，没有 git/VSS 可恢复，最后靠
    "已知标题精确匹配 + 块级规则"重建回 993 行——**浪费了一整段纯属自找的时间**。

### 附录 B.1 · 三条最重要的缺口

**第 9、10、13、15、16 条有共同点：只靠"跑起来"发现不了。**它们需要：
- **主动怀疑自己的实现**（而不是解释论文）
- **打印中间量**（而不是只看最终指标）
- **在完成后还能再回头**（而不是把"跑通"当成"做完"）
- **逐条抄论文**（关键词搜索不够，公式参数要单独抄）**第 13、16 条是一对**：论文白纸黑字写了归一化和参数 *a*，我读过去了；实现的指标"看起来还行"（0.85、0.90），于是没有回头查。**结果是把自己的疏漏算成了论文的差距——而且是写进了正式报告的。****第 16 条比第 13 条更隐蔽**：关键词还能靠搜索兜住，**参数值只能靠人抄**。而且 8.1 的异常信号清单也抓不到它——`cos²+sin²=1` 对参数取任何值都成立，**"编码归一化"这项冒烟测试从头到尾都是绿的**。**第 18 条是另一类问题：它不是"实现错了"，而是"结论范围没界定"。**数字对齐了、对照也做了，但如果没做"去掉方法"的基线，就会把一个**无法区分方法**的结果当成**验证了方法**的结果报出去。这是把话说大了，和把 bug 报成论文的问题是同一类错误的镜像。**第 22~26 条有一个共同点：它们保护的是"结论"本身，不是"实现"。**暴力对照、优化器不变量、图不可读数、不利结果一并报、日志落进流程——**这五条管的都是"我凭什么这么说"，而不是"我算得对不对"。****第 26 条是这份文档自己的病**：教训写进了变更日志，却没改进操作步骤。**改文档和改流程是两件事，前者容易后者难。** 唯一能防的办法是把它也做成一条要打勾的清单项。

> ## 全篇的一句话内核
>
> **结果对不上时，第一个该怀疑的是自己的实现，而不是论文。**
> **而"完成"之后，还要再怀疑一次。**
> **数字对上了，还要问一句：不用这个方法，能不能得到同样的数字？**
> **而"我复现出来了"这句话之前，还要问一句：这个结论经得起换一种做法吗？**
