# 任务模板与验收

先完成所选版本的安装或资料读取检查。以下路径、参数与预算都是示例，使用前按实际任务替换。

## 1. 新论文：只分析规格与可行性

```text
请使用已提供的论文复现工作流。
论文：papers/paper.pdf
目标：核对Table 1的分类实验。
本轮只读，不安装、不执行外部代码、不训练。
请给出论文身份、目标指标、数据划分、预处理、公式参数、
训练协议、官方代码可用性及最小验证计划。
关键参数标出处，未声明项单独列出。
```

验收：原文值与假设分开；计划未伪装成结果；官方来源核实不只依赖关键词。

## 2. 只复现官方仓库

```text
论文：papers/paper.pdf
官方仓库：vendor/official-repo
本轮只复现这个官方实现，不接受自实现替代。
先读README与入口，核对论文实验对应关系及依赖。
只允许读取；路径失效、依赖不明或缺少对应入口时，
记录L1-blocked与原因，并给出恢复该路线所需的最小信息。
```

验收：不擅自改为 L2 自实现；不把可读代码当作已经成功运行。

## 3. 允许无官方实现时自实现

```text
目标：复现论文的指定实验。
核查后没有可用官方实现时，允许按论文规格自实现。
先落盘规格表和最小实现方案，再在授权范围内推进。
提供核心数值对照、适用时的梯度校验和退化/等价性验证。
无法构造的检查标注原因，单独核对输入表示与评价协议。
```

验收：实现能对应论文规格；检查能区分错误实现；缺失项不会被“全部通过”掩盖。

## 4. 继续已有项目

```text
先读项目README、工作日志、配置和最近的真实运行日志。
不要从头重做，也不要依据旧聊天假定当前状态。
本轮目标：[具体目标]
允许操作：[范围]
剩余预算：[时间与计算限制]
简述当前事实和未决项，再继续有证据支持的下一步。
```

验收：较新证据优先于过时摘要；不重复已完成且有证据的步骤。

## 5. 指标异常或 NaN

```text
日志：[路径]
配置：[路径]
预期与实际差异：[说明]
本轮先分析现有证据，不能追加训练预算。
检查有限值、输入规格、梯度/更新链路和评价口径，
区分已确认错误、待检验解释和无法判断项。
允许修复恢复既定语义的实现错误；改变模型或协议另列方案。
```

验收：不先要求更多 epoch；没有证据时不归因于论文；修复与研究改进分开记录。

## 6. 已授权的有限扫描

```text
允许在独立结果目录扫描学习率[0.001, 0.003, 0.01]。
固定数据划分、种子及其余配置，每组最多2分钟，总计最多6分钟。
只使用验证集选择，测试集不参与调参。
保留每组命令、配置、状态、耗时和指标，包括失败组。
超预算就停止启动新组，不扩大搜索范围。
```

验收：仅运行给定集合；失败也入表；有限扫描不被表述为所有参数下成立。

## 7. 只设计方案

```text
设计一个有界超参数扫描方案。
本轮只写方案，不安装依赖、不启动实验或训练进程。
列出候选、控制变量、预算估算、成功标准与证据保存方式。
```

验收：输出方案与估算，不声称取得了实测指标。

## 8. 准备最终交付

```text
复查现有报告、结果文件和复算脚本，整理交付。
逐项标注哪些数字能从保存结果重算，哪些来自论文或图中估读。
区分已验证、未完成、无法判断，保留对当前结论不利的结果。
说明环境、数据、配置、命令、输出位置及适用范围。
本轮不新增训练，缺证据就标缺口，不补写虚构日志。
```

验收：单次跑分不当作稳定性证据；估读数有明确来源；结论不超出实验覆盖范围。
