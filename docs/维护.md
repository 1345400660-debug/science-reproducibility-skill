# 维护与生成产物

## 只改源文件

- 技能入口：`skills/paper-repro-pipeline/SKILL.md`
- 方法论：`skills/paper-repro-pipeline/references/workflow.md`
- 五份纪律与模板：同一技能目录中的 `references/`、`templates/`
- 使用说明：`docs/安装.md`、`docs/通用使用.md`
- 统一版本号：`VERSION`

不要直接编辑 `dist/`、ZIP 或 `SHA256SUMS.txt`，这些均可由源文件重建。

## 构建与检查

使用 Python 3.10+，仅依赖标准库：

```bash
python scripts/build.py
python scripts/build.py --check
python -m unittest discover -s tests -v
```

构建生成两种交付形式、旧下载名的兼容别名、源文件哈希清单和 ZIP 校验值。`--check` 不写文件，源文件变了而产物没更新时失败。

构建将文本换行规范化为 LF。ZIP 固定时间戳、按名称排序并采用存储模式，避免不同压缩库版本引起字节变化；重复构建应产生相同产物。

## 检查真实技能发现

在仓库目录：

```bash
npx skills@1.7.2 add . --list
```

应只发现 `paper-repro-pipeline`。安装测试使用独立临时项目，确认方法论、五份纪律与模板全部复制到技能目录，不依赖其他本机路径。

发布到 GitHub 后，使用仓库地址再做一次发现和安装验证，避免仅本地成功。

## 自动检查

GitHub Actions 配置运行产物一致性检查和构建回归测试。远程工作流是否成功以实际 Actions 运行状态为准，不能仅凭 YAML 文件存在就写“CI 已通过”。

测试覆盖缺失资源、包内链接越界、源文件变更导致产物过期和两种交付包含同一份资源。这些不代替实际 Agent 行为验证或论文训练。
