# 从 B/C 双版本迁移到统一技能

## 为什么合并

过去 B 版的技能、方法论、安装模板与 C 手册分别维护，容易产生规则漂移。2.0.0 将研究方法与纪律统一收进 `skills/paper-repro-pipeline/`，其他分发形式由构建脚本生成。

| 旧位置 | 新位置/处理方式 |
|---|---|
| `skills/paper-repro-pipeline/SKILL.md` | 保持技能名，替换为统一入口 |
| 项目根的 `复现工作流/` | 当前方法论改读技能内 `references/workflow.md`；旧文档可自行留作历史，不再作为新技能权威 |
| 兄弟目录 `ai-research-reproduction/references/` | 必需文件移到本技能 `references/`；不要删除可能被其他技能使用的旧目录 |
| C 版单独手册和提示词 | 使用自动生成的通用包整体替换 |
| 强制创建 AGENTS.md、替换路径占位符 | 不再需要；工作区模板仅作可选接入 |

## 迁移步骤

1. 备份本地定制技能、旧工作区约定和旧手册。
2. 从 GitHub 安装新版完整 `paper-repro-pipeline`，或手动复制完整目录。
3. 合并工作区约定，移除只针对旧布局的绝对路径和兄弟目录要求。不要覆盖其他项目规则。
4. 在 Agent 中确认实际读到新版技能内的方法论和五份纪律资料。
5. 普通对话则一起更换通用手册和提示词，避免资料区仍检索到旧正文。

本项目不会移动用户自己的实验代码、数据或报告。旧同名完整外部技能也不属于本次清理对象。

## 兼容下载

根目录 `B-DSH版.zip` 和 `C-通用平台版.zip` 暂留为自动生成别名，分别与 `dist/paper-repro-pipeline.zip`、`dist/universal.zip` 字节一致。

旧 B 包内部结构已变，不保证旧的复制安装脚本继续适用。需要原历史包时从 Git 历史获取 2.0.0 之前的提交。
