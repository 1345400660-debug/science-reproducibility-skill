# 常见问题

## 为什么以前不能直接 npx 安装？

旧仓库主要提供 ZIP，安装器找不到仓库工作树中的 SKILL.md；技能还依赖自身目录外的资料。新版提供标准可发现路径，并将资料全部内置。

## 需要注册 npm 账号或发布 npm 包吗？

使用 `npx skills add 用户/仓库` 不需要给本技能单独发布 npm 包。npx 下载并运行现成的 skills CLI，它再从 GitHub 安装技能。

若希望命令变成 `npx 某个自有名称`，那是另一个 npm 可执行包发布任务，需要可执行入口和 npm 发布权限。本项目当前采用现成安装器，不创建同名 npm 包。

## npx 成功了为什么 Agent 没用？

安装、宿主发现、实际读取、遵守规则是不同层次。检查项目级与用户级副本、实际读取路径，以及宿主的刷新方式；再做只读验收。

## 还需要安装其他研究技能吗？

不需要。方法论和五份纪律资料全部随本技能提供；外部训练、调试和论文查询工具按环境能力选用。

## B/C 为什么还在下载列表？

仅为兼容旧链接，内容由统一源生成。B 是技能 ZIP 别名，C 是通用 ZIP 别名。不是两套维护版本，B 内部安装布局已经变化。

## 是否自动获取算力、数据和依赖？

不会。具体论文的环境、数据和预算需要另行准备；只读任务不执行，官方仓库限定任务不擅自转自实现。

## 如何验证下载？

使用根目录 SHA256SUMS.txt。PowerShell 可运行：

```powershell
Get-FileHash -LiteralPath '.\B-DSH版.zip' -Algorithm SHA256
Get-FileHash -LiteralPath '.\C-通用平台版.zip' -Algorithm SHA256
```

具有 sha256sum 的环境，在仓库根目录执行：

```bash
sha256sum -c SHA256SUMS.txt
```

校验值必须来自同一版本；压缩包变化时旧校验值不适用。

## 如何升级、卸载或保留定制？

先备份定制。按安装说明更新指定技能，并重新验收；不覆盖自己的论文代码、数据和报告。生成文件不直接修改，研究规则改源文件后重建。

## 怎么反馈问题？

提供技能版本、安装器版本、宿主、最小提示词、实际路径和相关错误。账号凭据无需提供。明确问题是下载、发现、读取、规则还是实验执行阶段，有助于定位。
