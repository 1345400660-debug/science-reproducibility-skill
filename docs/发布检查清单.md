# 版本发布检查清单

只有完成下面四组检查，才把版本标记为稳定发布。

## 1. 版本和变更说明

- [ ] `VERSION` 是目标版本号，采用 `主版本.次版本.修订版本`。
- [ ] `CHANGELOG.md` 已说明新增行为、兼容性影响和仍未验证的边界。
- [ ] README 和安装文档没有引用旧版本或过期命令。
- [ ] 提交历史中没有把计划或目标值写成已验证结果。

## 2. 生成产物和本地验证

在仓库根目录执行：

```bash
python scripts/build.py
python scripts/build.py --check
python -m unittest discover -s tests -v
git diff --check
```

- [ ] 构建脚本成功完成。
- [ ] `--check` 报告所有生成产物与源文件一致。
- [ ] 全部回归测试通过。
- [ ] `SHA256SUMS.txt` 已由构建脚本更新。
- [ ] `dist/manifest.json`、ZIP 和通用资料来自同一个源版本。

## 3. GitHub Actions 和安装验证

- [ ] GitHub Actions 在目标提交上成功。
- [ ] 从 GitHub 仓库执行技能发现：

  ```bash
  npx skills add 1345400660-debug/science-reproducibility-skill --list
  ```

- [ ] 从 GitHub 仓库执行实际安装：

  ```bash
  npx skills add 1345400660-debug/science-reproducibility-skill \
    --skill paper-repro-pipeline
  ```

- [ ] 安装后的 `SKILL.md`、六份参考资料和两个模板与源文件一致。
- [ ] 安装目录中没有依赖仓库外的旧 B/C 文件。

## 4. 标签和发布记录

确认前面三组都通过后：

```bash
git status --short
git tag -a vX.Y.Z -m "Release vX.Y.Z"
git push origin vX.Y.Z
```

- [ ] 工作树干净。
- [ ] 标签版本与 `VERSION`、CHANGELOG 一致。
- [ ] GitHub Release 说明包含验证命令和证据链接。
- [ ] 发布后再次打开 README，确认安装命令仍指向正确仓库和技能名。

发布后如果发现问题，先记录影响范围和可复现命令，再决定修订版本或撤回标签；不要静默覆盖已有发布说明。
